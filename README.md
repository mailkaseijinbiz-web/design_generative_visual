# 感性モーフ（Kansei Morph）

市場を**感性デザイン9項目**（山岡俊樹編『デザイン人間工学の基礎』pp.238-240）の軸で地図にし、空いている場所を指して、そこに置く姿をAIに描かせるためのプロトタイプ。

`index.html` をブラウザで開くだけで動く。ビルド不要、依存なし。UIのトーンはNotionに寄せてある（白地・淡い罫・青のアクセント・角丸）。閲覧者の設定に関わらず**白背景で固定**している。

アイコンは **Google Material Symbols**（Apache-2.0）のアウトラインをSVGパスとして本体に埋め込んである。フォントやCDNの読み込みはしないので、`file://` でもオフラインでも同じように出る。

---

## 何が新しいのか

生成AIに「モダンでおしゃれにして」と頼むのは、印象語をそのまま投げているだけで、**何をどれだけ動かしたのか**が残らない。9項目はもともと *評価* のチェックリストなので、これを地図の軸にすると、指した場所そのものが指示になる。

```
市場を9項目に写像して地図にする
      ↓
空いている場所を押す ─ そこが狙う領域になる
      ↓
狙いの分だけ手本からずらした姿を、AIが描く
      ↓
描いた姿を地図に置く ─ 競合と同じ土俵で見比べる
```

画面は **マップ** と **設定** の2枚だけ。中間の作業タブは持たない。押した場所が指示になり、描かれた姿が地図に戻ってくる、という一本の流れに畳んである。

差分（Δ）が改変の指示そのものになるので、「彩度を上げた」ではなく **「色彩を 2→5 に上げ、形態は動かさなかった」** という、後から検証・再現できる形で記録が残る。

## 9項目を2種類に分ける

このプロトタイプの設計上の要点。9項目のうち、画像の画素をいじって表現できるのは6項目だけで、残り3項目は*構造*の話なので画素操作にすると嘘になる。地図の軸としてはどちらも等しく使えるが、指示文の書き方を分けてある。

| # | 項目 | 画素で表現 | 指示文での扱い |
|---|------|-----------|----------------|
| 1 | 雰囲気 | ○ | 露出・暖色・ブルーム／周辺減光 |
| 2 | デザインイメージ | ○ | コントラスト・色温度・輪郭 |
| 3 | 色彩 | ○ | 彩度・自然な彩度・白混ぜ |
| 4 | フィット性 | ✕ | **構造**：接触部を身体の曲率に沿わせる／分ける |
| 5 | 形態 | ○ | 階調量子化／ディテール強調 |
| 6 | 機能性・利便性 | ✕ | **構造**：操作数・手順の見える化 |
| 7 | 質感 | ○ | 局所コントラスト・粒状／平滑化 |
| 8 | 新しい組み合わせ | ✕ | **構造**：素材と技術の組み合わせ |
| 9 | 意外性 | ○ | スプリットトーン・色ずれ |

画素演算では届かないフィット性・機能性・新しい組み合わせも、生成モデルへの指示文としては「部品点数を減らす」「接触面を身体に沿わせる」という言葉で渡せる。これが出口を画像生成にした理由。

## マップ

**Googleマップのような全画面レイアウト**。地図が画面いっぱいに敷かれ、操作は地図そのもの（軸名のピル／ホイール／ドラッグ／ダブルクリック／ドロップ）に寄せてある。器の実寸をそのまま内部座標に使うので、ウィンドウを広げた分だけ地図も広くなり、縦横比は崩れない。

### 地図を読む

- **軸名を押すと、項目を選び直すダイアログが開く**。軸名は高さ40pxの青いピルで、文字も矢印も白。影も枠線も付けない。軸の変更はここに集約してあるので、地図の上に選択欄を並べていない。両端にはその軸の意味（複雑・装飾的 ←→ 単純・純化）を、枠の端から離して置いている。
- ダイアログの一覧は**ばらつきの大きい順**。ばらつきが大きいほど濃い青、ばらつきなしは濃いグレー、未測定は薄いグレーで色分けしてあるので、開いた瞬間に「効く軸」が上に固まって見える。**同じ項目を2つの軸に選ぶことはできない**（「X軸で使用」「Y軸で使用」と明示される）。
- 軸の両端には**矢印**を添えてあり、横軸は左右、縦軸は上下のどちらへ伸びる向きかがひと目でわかる。
- **サンプル画像の大きさは自動で決まる**。隣り合う塊との距離と、同じ値に重なっている点数から、ぶつからない上限を取っている。拡大すれば点の間隔が開くので、写真も自然に大きくなる。
- **ホイールで拡大、ドラッグで移動、ダブルクリックで表示を戻す**。方眼のドットは0.1刻みで1〜5の外側にも敷いてあり、拡大すると自動的に目が細かくなる。ドットは1px前後で、**密度の高いところでは青く染まる**（ヒートマップと同じ場をサンプルしている）ので、方眼と密度がひとつの層として読める。
- 背景は密度のヒートマップ。各点にガウス核を撒いて連続した密度場を作り、青一色の逐次配色で塗っている。最も広く空いている区画には「空白」と出る。
- **市場の重心**を赤い十字で示す。狙う領域には**旗**が立つ。
- **6テーマすべてに画像サンプルを同梱**している。椅子は**実写30点**（`samples/chairs.js`）。読み込み時に各点を自動推定し、9項目の空間で **k-meansクラスタリング** して群に分ける。群の名前は、その群を最も特徴づけている項目から自動生成される（例：「色彩が高い群」）。
- 残る5テーマ（メガネ35／冷蔵庫30／CT・MRI 24／産業機械29／バス27点）は、**アプリ自身の3Dレンダラで事前描画したサンプル**（`samples/renders.js`）。各テーマの市場分布（カテゴリ別プロファイル＋揺らぎ）どおりの姿を1点ずつ描いてあり、プロファイルは既知なので推定を通さずそのまま載る。実写に差し替えるときは同じ形式（`{id, cat, ci, name, p, src}`）に合わせるだけでよい。
- **ズームアウトしているときだけ、群が地図の上に出る**。破線の楕円がその群の広がり（1σ）で、肩に「色彩が高い群 14件」のような見出しが付く。拡大すると個々の商品を見る局面なので、じゃまにならないよう消える。凡例の欄は置かず、地図そのものに載せている。
- 写真はわずかに角を丸め、影を落として浮かせている。枠線は引かない。**点にホバーすると写真が大きく開く**。
- 他の対象（メガネ／冷蔵庫／CT・MRI／産業機械／バス）は、カテゴリごとの代表プロファイルから生成した合成コーパスが初期値。
- **画像を地図にドラッグ&ドロップすると、自動推定で同じ座標系に乗る**。ボタンは置かず、地図そのものが受け皿になっている。

### テーマを検索して地図にする

上部の**検索ボックス**にテーマ（例：スニーカー）を入れると、**Wikimedia Commons から画像を25枚ほど集め、その場でポジショニングマップを作る**。

- 集めた画像は椅子の実写と同じ経路を通る：9項目を自動推定し、k-meansで群に分け、密度・重心・群の楕円つきで地図になる。検索したテーマは対象チップの並びに加わり、切り替えもできる。
- ライセンスと作者は各点が保持していて、**ホバーで出る**（例：CC0・作者名）。画像はこのブラウザのメモリにだけ置き、どこにも保存しない。
- 検索には**画像専用の関連度検索（MediaSearch）**を使う。説明文まで拾う全文検索と違い、被写体で並ぶ。使えない環境では全文検索に自動で落ちる。
- **並べるのは商品写真だけ**。二段の選別を通す。①外周の色ばらつきで背景の無地度を測り、情景写真（街並み・室内など）をその場で落とす（キー不要）。②GeminiのAPIキーが入っていれば、候補36枚を1回の呼び出しで判定させ、「対象が1点だけ大きく写っていて背景が無地か簡素（カタログ調）」の画像だけを残す。除外した枚数は検索ボックスの脇に出る。
- 検索はブラウザから `commons.wikimedia.org` のAPIを直接叩く（`origin=*` の匿名CORS）。**公開ページ（Vercel等）で動く**。外部通信が遮断された公開アーティファクトでは使えない。
- AIによる描画もそのまま動く。集めた写真が手本になるので、検索したテーマでも「この市場と地続きの新しい姿」を描ける。

Amazonや一般の画像検索からの収集は規約上ここからは踏み込めないので、経路は①検索（Wikimedia Commons）、②同梱サンプル、③画像を地図にドラッグ&ドロップ、の3つ。

### 狙う領域を指す

- **格子は引かない**。地図の空いているところを押すと、その周辺が狙う領域になる。押し直せば別の場所へ移せる。目盛に丸めた目標が必ず領域の中央にくる。投影を共有しているので、拡大しても領域は地図にぴったり追随する。
- 右のパネルには、まず**この狙いの題**が出る。市場の重心からどちらへ何段動くかを、**店頭に並んだときの呼び名**に言い換えている（例：「ピュア ミスト 椅子 R」「ヴィヴィッド ラップ 椅子 X」）。振り幅が大きいほど強い語が選ばれ、振り幅の合計が末尾のシリーズ記号を決めるので、同じ狙いには同じ名が付く。
- その下に**軸ごとの数値が一覧で並ぶ**。項目名・範囲・重心から見た方向（例：単純・純化側へ +2.5）と、**その軸だけ指定を外す×**が付く。片方だけ残せば、残った軸の帯だけが目標になる。
- さらに下に、同じ内容を**数値を使わずに言い直した3行**が出る。市場がどこに集まっているか、そこからどちらへどれくらい離れるか、その場所が空いているか混んでいるか。

### AIが描く

- **既定は手動**。目標を置くと「AIでこの位置を描く」ボタンが出て、押したときだけ描く（1枚ごとに料金がかかるため）。設定の「目標を置いたら自動で描く」をONにすると、置くだけで描き始める。自動のときは連続して置き直しても最後の一回だけを投げ、追い越された結果は捨てる。
- 手本は**狙う位置にいちばん近いサンプル画像**。狙う位置ぶんだけずらした新しい姿をNano Bananaに描かせる。同じ市場にある物の素材・作り・撮り方を手本にするので、出てくる絵が市場と地続きになる。手本の平均から何をどちらへ何段動かすのかも、指示文に入る（例：手本の平均は 2.8。そこから単純・純化側へ 1.7 動かす）。
- 手本が実写のテーマ（椅子）と、事前レンダのテーマ（その他5つ）で、指示文の言い回しが変わる。レンダが手本のときは「レンダの粗さは引き継がず、実物をスタジオで撮った製品写真の質感で描く」旨を明示するので、出力は写真調になる。
- 描いた姿は**正方形**で、**地図の狙った位置にそのまま置かれ、そこに残る**。別の場所を指しても前の絵は消えず、案が地図の上に溜まっていく。同じ位置を描き直したときだけ差し替わる。
- **コメントでディレクションできる**。「脚をもっと細く、座面を広く」のように書いて「この指示で描き直す」を押すと、その一文が【追加の指示】として指示文の末尾に足される。
- **生成済みの画像をタップすると、描き直さずにその画像が右に出る**。狙う領域もその位置に移るので、見比べてから「この指示で描き直す」で手を入れられる。空いている場所を押したときだけ、新しく描く。

### 一気に描く（3×3／4×4／5×5）

右のパネルの **「一気に描く」** で、両軸を刻んだ升目それぞれを狙いとして描き、地図に並べる。地図が案の一覧表そのものになる。升目は **3×3（9枚）・4×4（16枚）・5×5（25枚）** から選べ、**既定は3×3**。料金は枚数に比例するので、まず9枚で全体を掴み、良さそうな区画だけ細かく描き足すのが安い。

- **一気描きを始めると、既存の市場（写真・密度・群・重心）は自動で隠れ**、生成した案だけの一覧になる。「市場を出す」ボタンでいつでも重ね直せる。
- 進みは「描いています… 12/25枚」と出る。もう一度押すと**止まる**。
- 止めた後にもう一度押すと、**描き終えた升目は飛ばして続きから**描く。同じ絵を描き直して待たされることはない。
- 同時に投げる枚数は設定タブで選ぶ（4／8／13／25）。**既定は8枚同時**。多くすると速いがGoogle側の頻度制限に当たりやすくなるので、断られる枚数が増えるようなら下げる。
- 一気描きでは手本を2枚に絞ってある。送る量が減るぶん戻りが早い。
- 描けなかった升目は数だけ知らせる。もう一度押せば、その升目だけを描き直す。

### 描いた案は保存される

- **描いた案はこのブラウザ（IndexedDB）に自動保存**され、次回開いたときすぐ地図に載る。テーマごと・軸ペアごとに升単位で持つので、**軸を入れ替えても（縦横が逆でも）対応する位置に出る**。
- **「全軸ペアを描いて保存」**で、9項目の全36軸ペア×5×5＝**900升をまとめて描ける**。描き終えた升は飛ばすので、止めても途中から再開できる。クラウドのモデルでは実行前に概算額を確認する（ローカル生成なら無料・確認なし）。
- 設定の**「描いた案を書き出す」**で `gallery.js` がダウンロードされる。`samples/gallery.js` に置き換えてコミットすれば、**公開ページでも同じ案が最初から地図に載る**。同じ升に新しく描いた場合は、この端末の保存分が同梱分より優先される。

## 設定

- **2次元／3次元** — 地図を平面で見るか立体で見るか。既定は2次元。3次元にすると、ばらつきの大きい未使用の項目が自動で奥行きに入り、地図をドラッグして回せるようになる。
- **Gemini APIキー**、**モデル**、**同時に描く枚数**、**目標を置いたら自動で描く**（既定OFF）。
- **ローカル生成（$0）も選べる**。「ローカル（SD WebUI互換API）」を選ぶとURL欄が出る。Stable Diffusion WebUI（A1111）を `--api --cors-allow-origins=*` で起動するか、Draw Things のAPIサーバを有効にして使う。CORSで繋がらないときは同梱の中継 `python3 tools/localrelay.py` を起動して `http://127.0.0.1:8787` を開き、**URL欄を空**にする（ページと同じ配信元を通るのでCORS設定が不要になる）。指示文は内蔵の英語テンプレ（9項目の狙い→英語の描写）で送り、キー不要・枚数カウントも増えない。手本画像は使えない。M4 Pro 24GB なら SDXL Turbo/Lightning で1枚数秒、FLUX.1 schnell（量子化）で30秒〜1分が目安。
- クラウドのモデルは3つで、**既定はいちばん安い Imagen 4 Fast**（約$0.02/枚・**手本画像を渡せない**ので市場との地続き感は落ちる・探索向き）。ほかに **Nano Banana**（約$0.04/枚・手本つき・標準）と **Nano Banana Pro**（高品質・数倍高い・仕上げ向き）。同じキーでそのまま切り替えられ、選んだモデルはこのブラウザに保存される。安く回すなら、探索は Imagen 4 Fast、気に入った区画は Nano Banana で手本つきに、仕上げの数枚だけ Pro。
- **この端末で描いた枚数と概算額**（Nano Banana換算・$0.04/枚の目安）がここに出る。料金の実額はGoogle AI Studioの請求画面が正。Nano Banana Pro は1枚あたり数倍高いので、仕上げの数枚だけに使うのが安い。

### AI画像生成について

- Nano Banana系は `models/{model}:generateContent`、Imagenは `models/{model}:predict` を叩く。モデルは **Nano Banana（`gemini-2.5-flash-image`）**・**Nano Banana Pro（`gemini-3-pro-image-preview`）**・**Imagen 4 Fast（`imagen-4.0-fast-generate-001`）** から選ぶ。Googleが名前を変えたら、`index.html` の `#gen-model` の `<option value>` を書き換えれば追従できる。
- キーがAI Studioの**無料ティア**なら、日次の無料枠内は課金されない。枠と実額はAI Studioの請求画面で確認する。
- 正方形は `generationConfig.imageConfig.aspectRatio = "1:1"` で指定する。対応しないモデルに当たった場合（HTTP 400）は、その指定を外して一度だけ投げ直す。
- **Nano Banana Pro では出力解像度を最安の1Kに固定**（`imageSize:"1K"`）。Proは出力が4Kだと1K/2Kの約2倍かかる。Nano Banana は解像度によらず1枚定額（約$0.04）なので指定しない。手本として送る参照画像の解像度は料金にほぼ影響しない（1枚あたり$0.001未満）。
- **受け取った画像は320pxに縮小して持つ**（`GEN_KEEP_PX`）。APIの出力は1Kが下限の定額なので縮めても料金は変わらないが、1枚約2MB→約20KBになり、25枚並べてもページが重くならない。地図の表示は最大180pxなので地図上の見た目は変わらない（右パネルの拡大表示は多少甘くなる）。ローカル生成も320×320で頼むので、そのぶん速い。
- キーの置き場所は2通り。**①画面で入力**：そのブラウザの `localStorage`（`kansei-morph.gemini-key`）にだけ残り、「キーを消す」で消える。**②Vercelに保存**：プロジェクトの環境変数 `GEMINI_API_KEY` に置くと、同梱のサーバレス関数 `api/gen.js` が中継し、**ブラウザにはキーが一切渡らない**。ページは起動時に `/api/gen` へ問い合わせ、サーバにキーがあれば入力欄なしで動く（設定に「Vercelに保存済み」と出る）。
- ②の注意：**URLを知っている人は誰でもあなたのキーで生成できる**（中継先のモデルは許可制にしてあるが、課金はあなたに付く）。URLを共有するなら、VercelのDeployment Protection（パスワード等）を併用すること。
- **ローカルで `index.html` を開いたとき、または公開先に置いたときだけ動く**。公開アーティファクトは外部通信が遮断されている。
- ローカル生成を使うときは、ページも `file://` かローカル配信で開くのが確実。httpsの公開ページから `http://127.0.0.1` へは、ブラウザによっては（Private Network Access の制約で）弾かれることがある。
- ブラウザから直接APIを叩く方式なので、キーは自分のものだけを、自分の端末で使うこと。共有端末や配布物に入れてはいけない。

| 冷蔵庫 | 家庭用大型家電／台所に常在 | 機能性・形態・雰囲気 |
| CT・MRI | 医療機器／被検者は不安な状態 | 雰囲気・機能性。**意外性は禁忌** |

| バス | 公共交通／不特定多数が同時に使う | 機能性・色彩・形態 |
| 椅子 | 家具／資料でフィット性の例 | フィット性・質感・形態（実写サンプル30点） |

椅子以外のサンプル画像はアプリ自身の3Dレンダラによる事前描画で、外部素材は使っていない。全テーマに画像サンプルがあるので、AIによる描画はどの対象でも動く。

## 目盛について

9項目の評価は1〜5の5段階を基準にしつつ、**0.5刻み**で置ける（3.5＝3と4の間）。刻みは `index.html` の `STEP` 定数一つで決まるので、0.25や0.1に変えることもできる。

## 自動推定について

読み込んだ画像から、平均輝度・輝度分散・彩度・カラフルネス（Hasler-Süsstrunk 近似）・輝度勾配を計算して初期プロファイルを置く。勾配は強弱で二つに分け、**強い勾配＝輪郭の多さ（形態）／弱い勾配＝肌理（質感）** として別々に効かせている。

推定するのは9項目のうち5項目まで。**意外性・フィット性・機能性・新しい組み合わせは画像統計から測れない**ので推定せず、人の評価に委ねている。

## 構成

```
index.html          アプリ本体（単一ファイル、依存なし）
samples/chairs.js   椅子の実写サンプル30点（560px / JPEG q62 を data URI で同梱）
samples/renders.js  他5テーマの事前レンダ145点（448px / JPEG q55、アプリ自身の3Dレンダラで自動生成）
samples/gallery.js  描いた案の同梱ファイル（初期は空。設定の「描いた案を書き出す」で差し替える）
api/gen.js          Geminiへの中継（Vercelサーバレス関数。環境変数 GEMINI_API_KEY を使う）
tools/localrelay.py ローカル実行用の配信＋Draw Things/A1111中継（python3標準ライブラリのみ）
vercel.json         静的配信の設定（ビルドなし）
```

## 公開する

ビルド工程がないので、静的ホスティングにそのまま置ける。**Vercelなら、このリポジトリをImportして「Other」プリセットのままDeployするだけ**（Build Command・Output Directory は空のまま）。`vercel.json` が置いてあるので追加の設定は要らない。

公開先に置くと、**AI画像生成が実際に使えるようになる**。キーは利用者が各自のブラウザに入れるか、Vercelの **Settings → Environment Variables** に `GEMINI_API_KEY` を追加して**サーバ側に一括で置く**（追加後はRedeployが必要）。サーバ側に置いた場合の注意は上の「AI画像生成について」を参照。

サンプルを1ファイルに埋め込んでいるのは、`file://` で開いてもキャンバスが汚染されず解析できるようにするため。差し替えるときは `window.__CHAIRS = [{id, src}, ...]` の形式に合わせる。

## 発展のさせ方

- **生成モデルの差し替え** — いまはGeminiの画像モデルに繋いである。1枚を描く処理は `drawOne()` 一箇所にまとめてあり、側面の描き直しも5×5の一気描きも同じ道を通る。指示文の組み立ては `sideGenPrompt()` に分けてある。
- **一気描きの刻み** — `GRID_AT` を `[1, 2, 3, 4, 5]` から変えれば、7×7でも0.5刻みでも同じ仕組みで回る。同時本数は `#gen-lanes` で決まる。
- **実収集パイプライン** — 商品APIや画像検索で集めた画像を地図に落とせば、そのまま市場マップになる。カテゴリはクラスタリングが自動で付ける。
- **評価ログ** — 誰が・どの案を・どの軸で選んだかを蓄積すると、組織としての感性の傾向が可視化できる。

## 制約

- 描いた姿はメモリ上にだけ持つ（`state.gallery`）。再読み込みすると消える。
- 頻度制限はGoogle側の都合なので、同時本数を上げすぎると断られる枚数が増える。断られた升目は数で知らせるだけで、自動では投げ直さない。
- 参照した講義資料の図版はリポジトリに含めていない。
- AI画像生成はブラウザから直接APIを叩く前提なので、実運用ではサーバ側でキーを保持する形に置き換えること。
