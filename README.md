# 感性モーフ（Kansei Morph）

既存のデザインを、**感性デザイン9項目**（山岡俊樹編『デザイン人間工学の基礎』pp.238-240）の軸に沿って改変していくためのプロトタイプ。

`index.html` をブラウザで開くだけで動く。ビルド不要、外部通信なし。UIのトーンはNotionに寄せてある（白地・淡い罫・青のアクセント・角丸）。閲覧者の設定に関わらず**白背景で固定**している。

---

## 何が新しいのか

生成AIに「モダンでおしゃれにして」と頼むのは、印象語をそのまま投げているだけで、**何をどれだけ動かしたのか**が残らない。9項目はもともと *評価* のチェックリストなので、これを操作盤にすると、改変が次の閉じたループになる。

```
① 調査 ─ 競合を9項目に写像し、混んでいる所と空いている所を見る
      ↓
② コンセプト ─ 用途文脈 × 市場の空き × 伸びしろ で、伸ばす項目を決める
      ↓
③ 可視化 ─ 目標プロファイルを3D形状と画像の両方で見る
      ↓
④ 評価 ─ 差分の妥当性を検査し、指示書として書き出す ─→ ①へ
```

差分（Δ）が改変の指示そのものになるので、「彩度を上げた」ではなく **「色彩を 2→5 に上げ、形態は動かさなかった」** という、後から検証・再現できる形で記録が残る。

---

## 9項目を2種類に分ける

このプロトタイプの設計上の要点。9項目のうち、画像の画素をいじって表現できるのは6項目だけで、残り3項目は*構造*の話なので画素操作にすると嘘になる。役割を分けてある。

| # | 項目 | 画像 | 3D | 実装 |
|---|------|------|-----|------|
| 1 | 雰囲気 | ○ | ○ | 露出・暖色・ブルーム／周辺減光、3Dでは環境光と背景 |
| 2 | デザインイメージ | ○ | ○ | コントラスト・色温度・輪郭、3Dでは稜線の描画 |
| 3 | 色彩 | ○ | ○ | 彩度・自然な彩度・白混ぜ |
| 4 | フィット性 | ✕ | ○ | **3Dでのみ**：接触面が身体を受ける皿に変形する |
| 5 | 形態 | ○ | ○ | 階調量子化／ディテール強調、3Dでは部品点数と面数 |
| 6 | 機能性・利便性 | ✕ | ○ | **3Dでのみ**：操作部の寸法と明快さ |
| 7 | 質感 | ○ | ○ | 局所コントラスト・粒状／平滑化、3Dでは面の肌理と光沢 |
| 8 | 新しい組み合わせ | ✕ | ○ | **3Dでのみ**：差替部品の素材が入れ替わる |
| 9 | 意外性 | ○ | ○ | スプリットトーン・色ずれ、3Dでは一部品の色相反転 |

2Dの画素演算では届かなかったフィット性・機能性・新しい組み合わせが、3Dでは実際の形として動く。これが可視化を3Dにした理由。

## ① 調査

競合を9項目に写像し、どこが混んでいてどこが空いているかを見る。

- **軸ごとのばらつき**（コーパス内の標準偏差）を軸の選択肢と一覧に出す。ばらつきのない項目・そもそも測れていない項目は「―／未測定」として区別できる。
- **軸を切り替えると、商品の写真が新しい位置へ滑らかに移動する**（密度の場も一緒に動く）。
- 軸の見出しは中央に項目名、両端にその意味（例：均質・無機的 ←→ 素材感がある）。
- **軸は1〜3項目まで選べる**。1つなら帯（同じ値は縦に積む）、2つなら平面、**3つなら立体**（ドラッグで回転）。どの項目が横・縦・奥行きなのかは、軸名と両端の意味（例：複雑・装飾的 → 単純・純化）を軸見出しに出している。
- **ホイールで拡大、ドラッグで移動**。拡大すると方眼のドットが自動的に細かくなる。
- 背景は密度のヒートマップ。各点にガウス核を撒いて連続した密度場を作り、青一色の逐次配色で塗っている（オフスクリーンのCanvasで生成し、SVGに画像として敷く）。最も広く空いている区画には「空白」と出る。
- **市場の重心**を十字で示し、周りの破線はばらつき（1σ）。自社の現状が集団のどこにいるかがわかる。
- **椅子は実写サンプル30点**（`samples/chairs.js` に同梱）。読み込み時に各点を自動推定し、9項目の空間で **k-meansクラスタリング** して群に分ける。群の名前は、その群を最も特徴づけている項目から自動生成される（例：「色彩が高い群」）。
- **点にホバーすると写真が大きく開き、クリックするとその一脚が「現状」になる**。調査から評価までが同じ座標系で繋がる。
- このタブでは左の評価台帳を畳み、マップを主役に置く。
- 他の対象（メガネ／冷蔵庫／CT・MRI／産業機械／バス）は、カテゴリごとの代表プロファイルから生成した合成コーパスが初期値。
- 「画像から追加」で手元の画像を放り込むと、自動推定で同じ座標系に乗る。「コーパスを保存」でJSONに出せる。

**Amazonや画像検索からの収集そのものは、このページの外側の仕事**。静的ページから直接叩くことはできないし、スクレイピングは規約上も踏み込めない。ここは収集結果の受け皿として、①同梱の実写サンプル、②画像の投げ込み、③JSON入出力、の3つの経路を用意してある。

## ② コンセプト

**市場マップにグリッドを切り、市場の重心からどの領域を目指すかを指定する**タブ。

- グリッドは2×2〜6×6から選べる。各セルにはその領域にいる競合の数が入り、色が濃いほど混んでいる。
- セルをクリックするとその領域が目標になり、重心から狙う領域へ破線が引かれる。「重心から見て形態は単純・純化側へ +2.5」のように、方向と量が言葉で出る。
- 選んだ領域は、その2項目の目標プロファイルとしてそのまま反映される。

あわせて、**どの項目を伸ばすべきか**を助言する。並び順は次の積。

```
スコア ＝ 用途文脈での重要度 × (0.35 + 0.65 × 市場の空き) × 伸びしろ
```

- **用途文脈での重要度**は対象ごとに持つ（メガネならフィット性1.0、産業機械なら機能性1.0）。
- **市場の空き**は「その項目で自分より上にいる競合の割合」の裏返し。**その項目を実際に評価できている競合だけを母数にする**ので、画像から測れない項目は「未測定」と表示され、中立値で扱われる。
- **禁忌**を持つ対象がある。CT・MRIと産業機械の「意外性」は上げてはいけない項目として、理由つきで警告に回る。
- 「目標に採用」で、その項目が目標プロファイルに反映される。

## ③ 可視化

**3D形状**と**画像改変**を切り替えられる。

- **3D形状** — Canvas 2D上に書いた簡易レンダラ（外部ライブラリなし）。対象ごとの部品構成を持ち、9項目の目標値がそのまま形状・素材・光になる。ドラッグで回転、自動回転あり。部品は役割（接触面／差替素材／操作部／装飾部／構造）で色分けして凡例に出る。
- **画像改変** — 既存画像に画素演算を適用する。比較バーで原画と重ねられる。下段の**派生案8点**は目標を±1〜2揺らしたもので、クリックで採用。

## ④ 評価

- 9軸プロファイル図（現状＝破線／目標＝実線）
- **妥当性チェック** — 禁忌に触れていないか／重要度上位の項目を動かしているか／動かす項目が多すぎないか（3件まで）／市場平均から離れる方向か埋没する方向か／構造項目を含むか
- 画像処理レシピ、設計指示書（コピー／JSON書き出し）
- **案の記録** — 複数案を残して呼び戻せる

## 対象（プリセット）

| 対象 | 用途文脈 | 効く軸／注意 |
|------|----------|--------------|
| メガネ | 装身具／一日中身につける | フィット性・質感・デザインイメージ |
| 冷蔵庫 | 家庭用大型家電／台所に常在 | 機能性・形態・雰囲気 |
| CT・MRI | 医療機器／被検者は不安な状態 | 雰囲気・機能性。**意外性は禁忌** |
| 産業機械 | 生産設備／安全と保守が最優先 | 機能性・色彩（視認性）。**意外性は禁忌** |
| バス | 公共交通／不特定多数が同時に使う | 機能性・色彩・形態 |
| 椅子 | 家具／資料でフィット性の例 | フィット性・質感・形態（実写サンプル30点） |

椅子以外のサンプル画像はすべてCanvasによる手続き生成で、外部素材は使っていない。

## 目盛について

9項目の評価は1〜5の5段階を基準にしつつ、**0.5刻み**で置ける（3.5＝3と4の間）。刻みは `index.html` の `STEP` 定数一つで決まるので、0.25や0.1に変えることもできる。

## 自動推定について

読み込んだ画像から、平均輝度・輝度分散・彩度・カラフルネス（Hasler-Süsstrunk 近似）・輝度勾配を計算して初期プロファイルを置く。勾配は強弱で二つに分け、**強い勾配＝輪郭の多さ（形態）／弱い勾配＝肌理（質感）** として別々に効かせている。

推定するのは9項目のうち5項目まで。**意外性・フィット性・機能性・新しい組み合わせは画像統計から測れない**ので推定せず、人の評価に委ねている。推定値は目安なので、`現状を評価` に切り替えて目で見て直すことを前提にしている。

## 構成

```
index.html          アプリ本体（単一ファイル、依存なし）
samples/chairs.js   椅子の実写サンプル30点（560px / JPEG q62 を data URI で同梱）
```

サンプルを1ファイルに埋め込んでいるのは、`file://` で開いてもキャンバスが汚染されず解析できるようにするため。差し替えるときは `window.__CHAIRS = [{id, src}, ...]` の形式に合わせる。

## 発展のさせ方

- **生成モデルへの接続** — 出力される指示文をそのまま画像生成／編集モデルに渡す。差し替え点は `renderPixels()` 一箇所。
- **実収集パイプライン** — 商品APIや画像検索で集めた画像を「画像から追加」に流し込めば、そのまま市場マップになる。カテゴリはクラスタリングが自動で付ける。
- **3Dの精度** — 現在の部品構成は各対象10〜20部品の概略。CADやメッシュを読めるようにすれば、同じ9軸の操作をそのまま実形状に効かせられる。
- **評価ログ** — 誰が・どの案を・どの軸で選んだかを蓄積すると、組織としての感性の傾向が可視化できる。

## 制約

- 画像の画素演算は 900px に縮小した表示解像度で行われる（保存もこの解像度）。
- 3Dは平面ポリゴンの塗り分け（陰面はペインタ法）で、影・反射・曲面の厳密さは追っていない。形の方向性を確かめるためのもの。
- 参照した講義資料の図版はリポジトリに含めていない。
