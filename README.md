# 感性モーフ（Kansei Morph）

既存のデザイン画像を、**感性デザイン9項目**（山岡俊樹編『デザイン人間工学の基礎』pp.238-240）の軸に沿って改変していくためのプロトタイプ。

`index.html` 単体で動く。ビルド不要、外部依存なし。ブラウザで開くだけ。

---

## 何が新しいのか

生成AIに「モダンでおしゃれにして」と頼むのは、印象語をそのまま投げているだけで、**何をどれだけ動かしたのか**が残らない。9項目はもともと *評価* のチェックリストなので、これを操作盤として使うと、改変が次の閉じたループになる。

```
① 現状を9項目で評価  →  ② 目標プロファイルを置く  →  ③ 差分＝改変レシピ
                                    ↑                        ↓
                                    └──── ⑤ 再評価 ←── ④ 改変結果
```

差分（Δ）が改変の指示そのものになるので、「彩度を上げた」ではなく **「色彩を 2→5 に上げ、形態は動かさなかった」** という、後から検証・再現できる形で記録が残る。

---

## 9項目を2種類に分ける

これがこのプロトタイプの設計上の要点。9項目のうち、画像の画素をいじって表現できるのは6項目だけで、残り3項目は*構造*の話なので画素操作にすると嘘になる。役割を分けてある。

| # | 項目 | 扱い | 実装 |
|---|------|------|------|
| 1 | 雰囲気 | 画像で改変 | 露出・暖色・ブルーム／周辺減光 |
| 2 | デザインイメージ | 画像で改変 | コントラスト・色温度・輪郭（クラシック↔モダン） |
| 3 | 色彩 | 画像で改変 | 彩度・自然な彩度・白混ぜ |
| 4 | フィット性 | 指示で改変 | 接触面と身体の関係 → 指示文 |
| 5 | 形態 | 画像で改変 | 階調量子化＋面統合／ディテール強調 |
| 6 | 機能性・利便性 | 指示で改変 | 操作数・手順 → 指示文 |
| 7 | 質感 | 画像で改変 | 局所コントラスト・粒状／表面平滑化 |
| 8 | 新しい組み合わせ | 指示で改変 | 素材・技術の組み合わせ → 指示文 |
| 9 | 意外性 | 画像で改変 | スプリットトーン・色ずれ／色相の収束 |

「指示で改変」の3項目は、画面には反映されない代わりに**設計指示書と生成AI向けプロンプト**として出力される。画素でできる範囲とできない範囲を、道具の側で正直に分けている。

## 画面（3面構成）

- **サンプル切替** — 観測窓の上に6対象のプリセット。切り替えると現状プロファイルが引き直される。
- **評価台帳** — 9項目のスライダー。`現状を評価` / `目標を決める` で編集対象が切り替わる。1本のスライダーに現状（○）と目標（■）の両方が乗り、その間が差分。
- **観測窓** — 改変結果のキャンバス。左右の比較バーで現状と重ねて確認できる。下段の**派生案**は目標プロファイルを±1〜2揺らした8案で、クリックするとその案が目標になる（＝探索が評価軸の上で行われる）。
- **差分と指示** — 9軸のプロファイル図（現状＝破線／目標＝実線）、画像処理レシピ、設計指示書。指示書はコピー、レシピはJSONで保存できる。

## サンプル対象（プリセット）

対象カテゴリが変われば、動かすべき軸も変わる。それを確かめるために、性格の異なる6対象を手続き生成で用意してある（外部素材は使っていない）。

| 対象 | 用途文脈 | この対象で効く軸 |
|------|----------|------------------|
| メガネ | 装身具／一日中身につける | フィット性・質感・デザインイメージ |
| 冷蔵庫 | 家庭用大型家電／台所に常在 | 形態・雰囲気・機能性 |
| CT・MRI | 医療機器／被検者は不安な状態 | 雰囲気・色彩（意外性を上げてはいけない対象） |
| 産業機械 | 生産設備／安全と保守が最優先 | 機能性・利便性・色彩（視認性） |
| バス | 公共交通／不特定多数が同時に使う | 色彩・形態・機能性 |
| 椅子 | 家具／資料でフィット性の例 | フィット性・質感・形態 |

用途文脈は指示書の冒頭に入る。**CT・MRIで意外性を上げる指示**が出たらそれは設計として間違い、という判断が、その場で見えるようにしてある。

## 使い方

1. `index.html` をブラウザで開く（起動時はメガネ）。
2. プリセットを選ぶか、画像を読み込む／ドラッグ＆ドロップ／`Ctrl+V` で貼り付け。読み込み時に**現状プロファイルが自動推定**される。
3. `現状を評価` に切り替え、推定値を目で見て直す。ここは人間の仕事。
4. `目標を決める` で到達点を置く。観測窓が即座に追従する。
5. PNG／JSON／指示書を書き出す。

自動推定は、平均輝度・輝度分散・彩度・カラフルネス（Hasler-Süsstrunk 近似）・輝度勾配から初期値を置くもの。勾配は強弱で二つに分け、**強い勾配＝輪郭の多さ（形態）／弱い勾配＝肌理（質感）** として別々に効かせている。

推定するのは6項目のうち5項目まで。**意外性は画像統計から測れない**ので推定せず、フィット性・機能性・新しい組み合わせと同じく人の評価に委ねている。推定値はあくまで目安で、必ず人の目で上書きすることを前提にしている。

## 発展のさせ方

このプロトタイプは「①評価 → ②目標 → ③レシピ」までを人の手元で完結させることに寄せてあり、以下は自然な延長線。

- **生成モデルへの接続** — 出力される指示文をそのまま画像生成／編集モデルに渡す。画素操作では届かない「フィット性」「新しい組み合わせ」まで含めた改変ができる。9軸のΔがプロンプトの構造化された素性になる。
- **Adobe Firefly / 画像APIへの置換** — 現在の画素演算（彩度・粒状・ぼかし等）を外部APIに差し替えれば、同じ操作盤のまま出力品質を上げられる。差し替え点は `renderPixels()` 一箇所。
- **評価ログ** — 誰が・どの案を・どの軸で選んだかを蓄積すると、組織としての感性の傾向（＝「自社のデザインを自分の言葉で語れるか」）が可視化できる。
- **複数案の比較検討** — 派生案を保存して並べ、9軸プロファイルの距離で案同士を比べる。

## 制約

- 画素演算は 900px に縮小した表示解像度で行われる（保存もこの解像度）。
- 参照した講義資料の図版は本リポジトリには含めない。サンプルはすべて Canvas による手続き生成。
